# GamerClock 미니게임 플레이 테스트 — 2026-08-26

플레이어 입장에서 프로덕션(`gamerclock.com`)을 처음부터 끝까지 돌려 본 결과다.
확인 폭: 데스크탑 1280×800 · 모바일 390×844 / 375×667 / 430×932.
대상: `light-warrior` · `jonah-journey` · `wave-village-fishing` (+ 신규 `pilgrims-path`)

---

## 🔴 반드시 고쳐야 함

### 1. `light-warrior` 가 프로덕션에서 실행되지 않는다

`/play/light-warrior` 를 열면 **"빛의 모험을 준비하고 있어요" 로딩 화면에서 영구히 멈춘다.**

실측:
```
Phaser v3.90.0 부팅됨            ← 콘솔 로그 확인
canvas 540×960 생성됨            ← DOM 에 존재
어셋 18개 전부 HTTP 200          ← 누락 없음
#initial-loader  display:grid, opacity:1, z-index:30   ← 안 걷힘
```

게임은 **로딩 오버레이 뒤에서 이미 돌아가고 있다.** 로더를 제거하는 코드가 실행되지 않는다.
데스크탑·모바일 모두 동일. 12초 이상 기다려도 그대로다.

> 참고: 이 저장소는 작업 중 다른 세션이 계속 커밋하고 있었다
> (`index-C4RrB1b9.js` → `index-CNnS1f5y.js` 로 참조가 바뀌는 것을 목격).
> in-flight 상태일 수 있으니 **먼저 재현 확인**이 필요하다.
> 소스는 이 저장소가 아니라 별도 Vite 프로젝트이므로 번들을 직접 수정하지 않았다.

### 2. 아케이드(`/mini-games`)가 `/play` 셸을 통째로 건너뛴다

`src/app/mini-games/page.tsx` 의 링크가 이렇게 되어 있다.

```tsx
href: '/mini-games/light-warrior/index.html?pixel=1&v=1.0.22'   // ← raw iframe 직행
```

아케이드에서 들어온 사용자는 **`/play/<slug>` 를 거치지 않는다.** 그래서 전부 빠진다:

| 빠지는 것 | 결과 |
|---|---|
| 세션 생성 | 누가 언제 몇 명 플레이했는지 모른다 |
| 분석 이벤트 | `minigame_started` / `completed` 0건 |
| 인증 게이트 | 점수 저장 유도 없음 |
| 결과 패널 | 랭크·개인최고·다시하기 없음 |
| 캘린더 복귀 CTA | **리텐션 루프가 끊긴다** |

핸드오프 §2 는 "미니게임은 GamerClock 안의 리텐션 레이어이지 별도 목적지가 아니다"라고 못박는데,
지금 아케이드 경로는 정확히 별도 목적지로 동작한다.

게다가 `v=1.0.22` 로 버전이 고정되어 있어 **아케이드로 들어오면 구버전이 뜬다**
(현재 매니페스트는 1.0.31+).

**고치는 법**: `href` 를 `/play/<slug>?source=arcade` 로 바꾸면 끝이다. 디자인은 그대로 둬도 된다.

### 3. 게임 목록이 카탈로그와 어긋난다

- 페이지에 **"3 games available now"** 가 하드코딩 (실제 4개)
- **천로역정이 아케이드에 아예 안 보인다** — 카탈로그 API 에는 있는데 페이지엔 없다
- 게임 목록이 `page.tsx` 안에 별도 배열로 박혀 있어 `MINI_GAMES` 와 이중 관리다

게임이 늘어날 때마다 두 곳을 고쳐야 하고, 한 곳을 빠뜨리면 지금처럼 어긋난다.
`MINI_GAMES` 를 단일 출처로 쓰고, 카드용 이미지·문구만 매니페스트에 추가하는 게 맞다.

## 🟠 강하게 권장

### 4. 첫 화면이 빈 사각형이다

| 게임 | 증상 |
|---|---|
| `jonah-journey` | 클릭하기 전까지 **빈 베이지 사각형**. 안내 문구 없음 |
| `wave-village-fishing` | 버튼이 "그래픽 준비 중…" 으로 몇 초간 비활성처럼 보임 |

데스크탑 사용자는 "안 되는구나" 하고 나간다. 모바일은 오디오 언락 때문에도 첫 탭이 필요하다.

`pilgrims-path` 에 넣은 **시작 게이트**("클릭해서 시작 + 조작 안내")를 공유 패턴으로 빼면
네 게임이 같이 해결된다. 첫 탭이 곧 오디오 언락이자 포커스 확보다.

### 5. 세로 게임이 가로 화면의 70% 를 버린다

`jonah` · `light-warrior` 캔버스는 540×960 세로다.
데스크탑 1280 에서 좌우가 텅 빈 채로 386px 만 쓴다.

그 빈 자리는 리텐션 CTA 를 놓기 가장 좋은 자리다 — 리더보드, 다음 이벤트, 다른 게임.
지금은 그냥 검은 여백이다.

### 6. 셸은 영어인데 게임은 한국어다

```
헤더: "Warrior of Light · Guest play is ready now"
게임: "빛의 모험을 준비하고 있어요"
```

대상이 아이라면 특히 어색하다. 셸에 한국어 문자열을 넣거나,
컨텍스트의 `locale` 로 셸 카피를 맞춰야 한다.
(`pilgrims-path` 는 컨텍스트 `locale` 을 받아 게임 쪽 언어를 맞추도록 해 뒀다 — 셸은 아직 영어다.)

### 7. 데스크탑에서 가상 조이스틱이 뜬다

`jonah` 는 데스크탑에서도 화면에 가상 스틱과 액션 버튼을 띄운다.
키보드로도 되는지 알 수 없고, 마우스로 스틱을 끄는 조작은 불편하다.
포인터 종류(`pointer:coarse`)로 갈라야 한다.

### 8. `scoreChanged` 를 아무도 안 쓴다

| 게임 | ready | started | completed | scoreChanged |
|---|:--:|:--:|:--:|:--:|
| wave-village-fishing | ✓ | ✓ | ✓ | ✓ |
| light-warrior | ✓ | ✓ | ✓ | ✗ |
| jonah-journey | ✓ | ✓ | ✓ | ✗ |
| pilgrims-path | ✓ | ✓ | ✓ | ✓ |

`completed` 만 있으면 **끝까지 간 사람만** 보인다.
어느 챕터에서 이탈하는지 모르면 어디를 고쳐야 할지도 모른다.
장/스테이지가 넘어갈 때 한 번씩만 보내면 충분하다(매 프레임 금지, 핸드오프 §14).

## 🟡 그 외

### 9. `_bible-shared` 미사용 번들 약 92MB
번들 69개 중 실제 참조 5개. 다른 세션이 사용 중이라 손대지 않았다. 절차는 핸드오프 §27.

### 10. 아이프레임 sandbox 경고
```
An iframe which has both allow-scripts and allow-same-origin can escape its sandboxing.
```
같은 출처 게임이라 의도된 구성이지만(§17), 콘솔에 매번 뜬다. 알고 있는 상태로 두면 된다.

## 권장 처리 순서

1. **1번** 확인 — 재현되면 라이브가 깨진 상태다. 가장 급하다.
2. **2번** — `href` 한 줄씩만 바꾸면 리텐션 루프가 살아난다. 비용 대비 효과 최고.
3. **3번** — 목록을 `MINI_GAMES` 단일 출처로.
4. **4번** — 시작 게이트 공유 패턴화.
5. 나머지는 다음 사이클.
